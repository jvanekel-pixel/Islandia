# Audit detail — blueprint Phases 4, 5, 7 (foliage, architecture, on-device glTF loading)

Sources: `docs/blueprint/phase-04.md`, `phase-05.md`, `phase-07.md`; drafts under
`reference/drafts/Assets/`. glTFast usage was checked against the 6.10.0 source and URP usage
against the 6000.0/6000.3 `Lit.shader`; anything else is marked unverified. Nothing was compiled.
Line numbers (L…) refer to the original single-file document; treat them as approximate pointers.

## Verdict

Trustworthy as API-shaped scaffolding. **Not trustworthy as content, integration or performance
evidence: no numeric gate is enforced or measured by any code.**

| Phase | Compiles unchanged | Behaviour |
| :-- | :-- | :-- |
| 4 Foliage | ~99% (one line) | Draws placeholder cones; batching keyed wrongly |
| 5 Architecture | 0% as pasted (escaped); after clean-up two one-line fixes | Weakest: weld-nearby is dead, undo is wrong, snapping and the catalogue are unwired |
| 7 glTF loading | ~100%, API use verified | Frame budget, texture flip, shader inclusion and accounting are wrong at runtime |

Three document-wide facts:

- Phase 5 was markdown-escaped end to end in the original. `tools/split_blueprint.py` has already
  cleaned it; `reference/drafts/` holds the cleaned code.
- **There are no assembly definitions.** Everything would land in one assembly, so one compile
  error blocks every phase, and tests cannot reference the game code.
- The original contains no batchmode step, no `-executeMethod`, no test, no always-included
  shaders, no shader variant collection.

## The content reality check

Every mesh and texture is generated by two editor wizards. There are no external assets.

**Foliage has four shapes** reused for all 111 archetypes:

- *Tree:* one tapered trunk cone plus five stacked open-bottomed cones — a 168-triangle Christmas
  tree (budget says 1,200) used unchanged for Coconut Palm, Baobab, Saguaro Cactus and Weeping
  Willow. A player standing under it sees a hollow.
- *Bush:* seven overlapping truncated cones, 112 triangles (budget 450).
- *Flower:* five three-sided stems with flat single-sided diamond petals, 90 triangles. All 32
  "species" are this one mesh.
- *Grass:* twelve loose single-sided triangles, about half back-face culled from any view.
- Variation: 36 trees differ by one of 7 faint tints; 42 bushes by one of 5; flowers by 10 palette
  rows. No tree or bush has petal-masked vertices, so Cherry Blossom and Azalea are plain green.

**Architecture has two shapes:**

- *"Gazebo":* eight single-sided roof triangles floating at 2.6–3.8 m. No plinth, no pillars.
- *Everything else:* a scaled Unity cube with every UV on one atlas point.
- Four prefabs exist. All 95 modules — stairs, roofs, bridges, across all five themes — map to the
  same 2 × 3 × 0.25 m wall box. All 20 rocks, 75 props and 15 media/pet items map to one glowing
  lantern box. The 75 props are literally named "Outdoor Living Furniture / Prop #N".
- Textures: a 256×64 gradient, a 512² four-colour Perlin "atlas" (not the 2048 ASTC claimed), a
  256² procedural matcap.

**Net: of 631 items there are about 6 distinct geometries and about 27 distinguishable looks.**
The architecture catalogue is referenced by no runtime code, so its 233 items are also unreachable
in-game.

To look good the project needs roughly 111 botanical and 230 architectural models with LODs, real
atlas UVs, per-module socket data and colliders. That is an art deliverable no step in the
blueprint produces. The plan's answer is the content track (`C-*`) and ADR-11.

## Defects

### Will not compile

- L6651: `public structLocalSocketPoint` — missing space; the mangled name is then used as a type.
  Phase 7 depends on this file.
- L7096: `ComponentType` needs `using GLTFast;`.
- L5459: `float4x4` has no `.m13`; it is `c3.y`.

### Verified library issues

- **Frame budget.** `SetFrameBudget` takes a fraction of the target frame, not seconds. Passing
  `0.002` gives about 67 µs per frame: loads crawl, and the "2.0 ms" gate is not what is configured.
- **Upside-down textures.** The material remap copies textures but not the scale/offset property
  glTFast uses to flip KTX textures — the exact format the pipeline emits. Alpha mode,
  double-sidedness and normal maps are also dropped.
- `link.xml` names `MeshoptDecompress`; the assembly is `Unity.Meshopt.Decompress`.
- The imported-model shader calls `SampleSHVertex` without defining the keyword that makes it
  return anything, so imported models get no ambient light.
- Confirmed valid for glTFast 6.10.0: the `GltfImport` constructor, `LoadFile`,
  `InstantiateMainSceneAsync`, import and instantiation settings, export settings, `AddScene`,
  `SaveToStreamAndDispose`, `ICodeLogger`.

### Logic

- **Weld-nearby always returns null.** It passes a scratch list as the candidate list and the
  callee clears that same list first. This is the exact call the Phase 5 acceptance step uses.
- At the 64,000-vertex cap the weld loop silently stops, leaving the rest un-welded. Only the
  first mesh filter and sub-mesh 0 of each object are welded.
- Undoing a weld hides the building *and* all its source modules.
- Media and pet props are flagged non-weldable in the catalogue but weldable on the prefab; the
  welder checks only the prefab.
- Snap position is computed with the un-snapped rotation. The snap function has no caller.
- **Foliage buckets are keyed by (species, LOD)** although tint and palette row are per instance.
  A garden using all archetypes costs 111 × LOD rings in draw calls, breaking the gate. Key by mesh.
- The toybox sends its own array index as the botanical ID; nothing fills that array. If the item
  has a prefab the plant renders twice.
- Instanced foliage cannot be undone or deleted; its 16,384 slots are never reclaimed.
- Every sculpt event re-samples all instances. Flowers below −0.30 m are deactivated permanently —
  including Lotus and Water Lily.
- Grass pops at 22 m, is seeded once in a fixed disc, and ignores what the terrain is painted with.
- Import budgets under-count: triangles from sub-mesh 0 only, draw calls as renderers not material
  slots. Counters are never decremented, quota is released only on failure, templates are never
  evicted — imports lock out after enough spawn-and-delete cycles.
- No in-flight de-duplication: two approvals of one model load twice and leak the first.
- The "SHA-256 content-addressable" cache never hashes the file.

### Works only in the Editor

- `Shader.Find` returns null in a player unless the shader is referenced or always included.
  Nothing does that, so the remap silently becomes a no-op on device.
- Any logged glTFast error fails the load, so glTFast's own shaders must also be in the build.

### Prose contradicted by code

- All shaders are called SRP Batcher compatible while using `UsePass` on Lit's passes.
- The welder is called "Burst-accelerated"; it is main-thread `CombineMeshes` plus a synchronous
  collider bake.
- The "full island snapshot" export cannot include instanced foliage, which has no GameObjects.

## Pre-agreed fallbacks (adopted in `02-ARCHITECTURE.md`)

1. **Inventory** → an honest, data-driven catalogue built from CC0 packs plus parametric
   generators, with CI asserting distinct-mesh count and triangle budgets. (ADR-11)
2. **glTF import** → a custom material generator passed into the importer instead of a post-hoc
   remap; bounds-based box or convex colliders; memory measured, not estimated; the gate restated
   as a maximum frame time measured on device. (ADR-12)
3. **Foliage rendering** → bucket by mesh first. If device behaviour is still poor, plain
   GameObjects with LOD groups and instanced materials for trees and bushes, custom instancing
   only for grass and flowers. **Welding** → one shared material may make it unnecessary; measure
   before building it. (ADR-17)
